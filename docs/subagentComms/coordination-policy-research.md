# Test the review process before adding orchestration

Primary-source review, 2026-09-21. The most useful candidate for Kimchi is an independent investigation followed by a reproducible finding and a check of the combined repair. Existing messages, board entries, shared files and TODO evidence can carry that work. Its benefit remains an experimental question.

The [previous six runs](communication-use.md) explain the choice. Explicit cross-review produced delivered questions and replies, but reviewers often agreed without testing the claimed behavior. Neither implementation owner published the final decision and test evidence. Four workers exhausted their limits. More communication occurred; better completed code was not established.

[AlphaEvolve](https://arxiv.org/html/2506.13131) supplies an earlier example of the evaluation loop: generate changes, execute independent checks, retain useful candidates and evaluate on held-out inputs. Its successes concern machine-gradeable optimization problems and substantial search. For Kimchi, the transferable part is selecting changes by measured outcomes; copying its evolutionary infrastructure is unnecessary.

## The candidate under test

The [experimental brief](../../scripts/agent-communication/evidence-review-brief.md) changes the review sequence. Each owner establishes a boundary case before reading peers' conclusions, records a reproduction or an explicitly unverified suspicion, then checks relevant peer evidence. Findings that affect another owner include the failure condition and requested correction. The parent reads the evidence and verifies the combined result.

The comparisons assign that same brief to solo, ordinary-worker and board-enabled runs, twice each, with the order reversed in the second block. Model, source, public checks and total budget ceilings stay fixed within each cohort. Ordinary workers retain shared files and parent coordination. Independent grading checks process behavior, lifecycle boundaries, refresh discovery, delayed fallback, protected edits and added tests. Earlier proposal-first runs remain background evidence, not matched controls for the brief itself. After GLM capacity failures, a separate K3 cohort completed all 12 runs across compaction and OAuth. The [results](evidence-review.md) show no complete compaction repair; ordinary workers and board each pass one of two frozen OAuth comparisons. The board's peer recovery hint was followed successfully, but that run's code still failed a timeout check.

This tests the available communication package under the same review task. Tool masking also removes communication guidance, so it cannot isolate transport from its instructions. Two repetitions per mode on previously observed tasks cannot establish general superiority. Keep communication optional: neither the measured outcomes nor inspection of recipient actions supports making this brief a default policy or adding another coordinator.
